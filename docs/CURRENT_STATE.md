# Текущее состояние

Снимок документации: 19 сентября 2026 года. Перед изменениями сверяйте его с кодом и `git log`, поскольку это не release automation.

## Runtime и данные

- Backend: FastAPI + SQLAlchemy; локально SQLite, deployment рассчитан на PostgreSQL.
- Production container: Python 3.13, `alembic upgrade head`, затем Uvicorn на `$PORT`.
- Alembic head: `20260828_01_payment_profiles`.
- Health-check: `/healthz`.
- Основной source remote: GitHub `origin`; deployment remote: `amvera`.

## Активные контуры

Web «Коммуналка» → «Календарь оплат»: календарь на странице без внутреннего вертикального скролла, с бесконечной горизонтальной шкалой, масштабом 10–200%, динамическими объектами/квартирами и переключением аренды/коммуналки. Видимые дни загружаются окнами по 120 дней (кеш до 8 окон), счета показаны полосами точных периодов с подсказками. Белые дни без счёта — до 31 дня назад, жёлтые — старше; красные — просроченные счета и пропуски перед позднее оплаченной коммуналкой того же договора/услуги. Отдельная сводка `/api/utilities/calendar/summary` позволяет перейти к скрытой просрочке за пределами загруженных окон. Backend `/api/utilities/calendar` читает договоры и финансовые строки без пересчёта; новые объекты не требуют изменений frontend. Цвет показывает текущую оплату периода, а не исторический снимок на выбранную дату.

Коммунальные черновики: периоды строк сохраняются структурированно; повторный расчёт учитывает интервалы выставленных строк, а web-группировка разделяет договоры одной квартиры. Предпросмотр отличает прежние долги от новых начислений и ограничивает их выбранным домом. Эти изменения требуют обновления backend/web; уже сохранённые черновики автоматически не пересчитываются.

- аренда, начисления, оплаты, коммуналка, расходы, долги, отчёты и imports;
- управление объектами/квартирами и reusable payment profiles с inheritance/override;
- owner/guest PIN sessions, settings encryption и admin backup/import endpoints;
- Telegram owner/tenant flows, webhook и reminders;
- DeepSeek adapter, owner operations и proposal confirmation;
- Hermes Core: events, cases, commitments, preferences, briefing, skills, safety, usage/runs и web/Android endpoints;
- browser UI в `static`: полный интерфейс по `designdoc.pen` с белой и неоновой темами, неоновая выбрана по умолчанию; отдельные постоянные разделы «Главная» и «Сегодня», компактная очередь решений из прежнего рабочего сценария, адаптивная навигация и нативный Android Java-клиент. Прежний экран загрузки сохранён, авторизация оформлена как отдельная неоновая welcome-поверхность.

Web-панель является текущей полной поверхностью управления Payment Profiles. Android получает созданные объекты и квартиры через общий registry, но отдельного редактора профилей в нём пока нет.

## Android

Архив договоров сохраняет долги и историю, отключая сообщения и автоначисления. Новые коммунальные начисления округляются вверх до 10 ₽ по каждой услуге. В диалогах сохраняются Telegram-автоответы и доступна вся сохранённая история.

- package: `ru.rentalmanager.mobile`;
- `versionCode`: `12`;
- `versionName`: `0.1.11`;
- SDK 35, min API 23 в custom build script;
- versioned APK создаётся как `android/RentalManager/build/rental-manager-mobile-<versionName>.apk` и игнорируется Git.
- Обновления проверяются при запуске, возвращении в приложение и через отдельный JobScheduler. APK автоматически скачивается по Wi-Fi/мобильной сети (кроме роуминга), проверяется по SHA-256/размеру/package/версии/подписи и устанавливается после системного подтверждения. Основной запрос — `/api/mobile-update`; при недоступном серверном APK используется публичный GitHub Releases этого репозитория. Публикация описана в [Android release](ANDROID_RELEASE.md).
- Проверки этапа обновлений: 312 backend tests + SQLite smoke, 12 Java policy assertions, сборка API35, установка APK поверх 0.1.7 на Android API36 с тем же сертификатом, JobScheduler зарегистрирован. Реальная доставка следующего обновления проверяется после публикации следующей версии.
- Версия 0.1.9: переработаны пять основных разделов, поиск квартир/оплат, денежный поток с авторитетной серверной сводкой и явным состоянием отсутствующих данных, карточки действий, отчёты и навигация к коммуналке/счётчикам/тарифам/расходам/договорам/чекам. Учтены системные панели и масштаб шрифта. Hermes пока использует прежний экран.
- Версия 0.1.11: полноэкранный контроль зарплатных платежей с навигацией по месяцам, именами жильцов и фильтрацией архивных ожидаемых начислений; долги и история архивных договоров сохраняются.
- Уведомления: сохранённый fingerprint событий исключает повторный сигнал без изменений; учитываются общий выключатель, категории и тихие часы, переходы ведут к рабочим разделам. Закреплённая сводка не подавляет новые события и не требует постоянного foreground service; по умолчанию выключена, явный выбор пользователя сохраняется. Настройки уведомлений переработаны с выбором времени и статусом системного разрешения.
- Проверки 0.1.9: 32 Java assertions (обновления и уведомления), native UI smoke на отдельном APK без INTERNET с синтетическими данными, обычным/увеличенным шрифтом и regression для отсутствующей месячной сводки. Полные backend проверки этапа 0.1.8 остаются актуальны: backend в 0.1.9 не менялся.

## Важные ограничения

- `rental_manager/main.py` остаётся крупным composition hotspot; бизнес-логику не следует дополнительно размножать в routes и клиентах.
- SQLite smoke не доказывает PostgreSQL indexes/constraints и production migration behavior.
- Реальные Telegram, DeepSeek, Amvera и Android signing проверки требуют внешних доступов и не считаются выполненными без явного evidence.
- Записанный в `TESTING.md` результат является историческим; для каждой задачи фиксируйте команды, выполненные в текущем checkout.

Обновляйте документ при изменении Alembic head, deployment startup, Android версии, поддерживаемых API/клиентов или статуса Hermes. Не используйте его как список коммитов.
