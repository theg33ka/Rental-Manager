# Мобильное приложение: этапы переработки

Задача от 19 сентября 2026 года. Только тёмная тема; автоматическая загрузка обновлений через Wi-Fi и мобильную сеть. Основная цель — завершать ежедневную работу на телефоне без ожидания доступа к компьютеру.

Каждый этап заканчивается целевыми проверками, увеличением Android версии, сборкой APK существующим ключом и push в `main`. APK публикуются вне Git. Договоры и финансовые таблицы остаются источником истины; клиенты используют backend операции и существующие подтверждения.

1. **Обновления.** Проверка при запуске, при возврате и в фоне; автоматическое скачивание; проверка версии, размера, SHA-256, package и подписи; понятная установка через Android. Реальная публикация APK через GitHub Releases, поскольку Amvera Docker не содержит APK.
2. **Рабочий интерфейс.** Единая тёмная визуальная система, навигация из пяти разделов, месячный денежный поток с данными backend, действия на оплатах и квартирах. Вернуть доступ к существующим счётчикам, тарифам, расходам и управлению договорами.
3. **Дополнительные сценарии и уведомления.** Согласованные формы, Hermes и настройки; полезные уведомления, защита от повторов, переходы к соответствующим задачам. Сохранить финансовые и safety подтверждения.
4. **Проверка целостности.** Проверить маршруты и состояния на Android-эмуляторе, установку поверх предыдущего APK, обновление через публичный канал, читаемость и отсутствие перекрытия системными панелями. Исправления выпускаются отдельным завершённым этапом при необходимости.
